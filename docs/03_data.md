# 03 Data

## Main dataset: 140k Real and Fake Faces

- **Source:** Kaggle, `xhlulu/140k-real-and-fake-faces`
- **Real faces:** 70,000 photos from Flickr-Faces-HQ (FFHQ), a public research dataset by NVIDIA
- **Fake faces:** 70,000 faces generated by StyleGAN
- **Image size:** 256×256 pixels
- **Balance:** 50% real, 50% fake
- **Licence:** for research and education. Check the Kaggle page before any other use.

### Splits
| Split | Images | Used for |
|---|---|---|
| train | 100,000 | Learning the model weights |
| valid | 20,000 | Choosing the best epoch and settings |
| test | 20,000 | Final reported results, used **only at the end** |

### Folder layout
After `make data`, the images are in:

```
data/raw/real_vs_fake/real-vs-fake/
├── train/{real,fake}/*.jpg
├── valid/{real,fake}/*.jpg
└── test/{real,fake}/*.jpg
```

If Kaggle changes the folder names, update `data.root` in `configs/base.yaml`.

## Labels
| Folder | Label | Meaning |
|---|---|---|
| `fake` | **1** | AI-generated, the thing we want to catch ("positive") |
| `real` | **0** | A genuine photo |

The model outputs `P(fake)`, a number between 0 and 1. By default, 0.5 or above means "flag as fake".

## Out-of-distribution (OOD) test set (optional, recommended)

The main dataset only has StyleGAN fakes. Real fraudsters use many tools, so we test on fakes from a **different** generator.

1. Collect a few hundred faces from another generator, such as diffusion-model faces from a public Kaggle dataset, plus the same number of real faces.
2. Put them in:
   ```
   data/ood/real/*.jpg
   data/ood/fake/*.jpg
   ```
3. Run:
   ```bash
   python -m deepfake_kyc.evaluate --checkpoint <ckpt> --data-dir data/ood --name ood
   ```

Write down where the OOD images came from in the report (source, licence, how many).

## Using a subset while developing
Training on all 100k images takes a while. While you're writing code, use a reproducible subset:

```bash
python -m deepfake_kyc.train --config <file> --set data.train_subset=10000 data.val_subset=2000
```

The subset is random but fixed by the seed, so everyone gets the same images.

## Data rules
- **Public data only.** No customer data, no work data from payments or law enforcement.
- **Never commit images** to git. `data/` is git-ignored.
- **Don't look at test-set results while tuning.** Use the validation set to make decisions, and run the test set once per final model.
- The real faces are real people from Flickr. Don't put them in public materials beyond a few examples in slides.
